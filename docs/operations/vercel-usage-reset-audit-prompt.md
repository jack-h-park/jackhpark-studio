# Prompt for an independent Vercel usage audit

Audit the current `jackhpark-studio` repository and Vercel Production usage from first principles. Establish the latest remote `main`, the actual Ready Production commit, the project/team scope, the current monitoring configuration, and the available data before reading the [prior retrospective](./2026-11-22-vercel-usage-recovery-retrospective.md). Use the retrospective afterward to check for omissions or contradictions. Treat each earlier conclusion, including any claimed savings, as a hypothesis to verify.

1. Read the authenticated free Vercel Usage/Observability views and bounded historical metadata. Verify team limits and rolling totals independently from Studio's project totals. Record explicit local/UTC bounds for equal, complete windows. Include route or traffic context and both raw figures and matched comparisons that exclude deployment, sitemap sweep, manual refresh, and other known intervention bands. Account for data lag, daylight-saving time, rounding, and expired history.
2. Trace recurring work in the current code and live configuration. Cover CDN and ISR, cache reads/writes and invalidation, request-triggered Notion rendering, image optimization and social images, API/SSR settings loads, cron/ingestion, external publisher tests, production smoke, Checkly, and deployment verification. Separate intentional work from redundant work. Check cold starts and regional cache behavior using real data. Use local sanitized fixtures with networking disabled for controlled CPU profiles where needed.
3. Report the known limits, each observed change and its evidence, and rank findings as **fix needed**, **intentional cost**, or **insufficient evidence**. For each candidate identify the precise path, what triggers it, how often it occurs, what breaks if changed, how to test freshness and failure behavior, and how to measure savings. Distinguish observed Production behavior, synthetic results, and causal claims. Prioritize free improvements and specify what would justify paid diagnostics.

Work in read-only mode during the initial audit. Keep the current checkout and unpublished work intact. Do not merge, deploy, change monitoring or retention, alter settings, upgrade, trigger ingestion or refresh, crawl Production, run additional smoke checks, contact paid providers, or inspect credentials. If a metric is missing, say what is unavailable and which read-only evidence could resolve it. Preserve manual refresh and admin-save freshness in proposed changes. Deliver a concise Korean report with source links and English text for any repository document.
